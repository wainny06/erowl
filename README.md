# 한의원 재고관리 — 비밀번호 없이 사용

사이트 주소를 아는 사람이 로그인 없이 재고 조회·입출고·품목 관리를 할 수 있습니다. 일별 재고 목록과 CSV도 사이트에서 바로 확인할 수 있습니다.

## 이번 변경

공용 비밀번호와 로그인 검사를 제거했습니다. `STOCK_PASSWORD`는 더 이상 사용하지 않으므로 설정할 필요가 없습니다. 로그인 화면의 이전 주소 `/login`은 현재 재고로 이동합니다.

현재 재고는 기존 Supabase를 사용합니다. 일별 재고 목록은 **Vercel Private Blob**에 저장하며 Supabase에 백업 테이블을 추가하지 않습니다.

## 설정 — Production

1. 기존 `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`를 유지합니다. 이미 `SUPABASE_SECRET_KEY`를 등록했다면 그대로 사용할 수 있습니다. 서버용 키가 있으면 우선 사용합니다.
2. 생성한 **Private Blob**을 `erowl` Production에 연결합니다. `BLOB_STORE_ID`가 Production으로 표시되면 자동 인증 연결입니다. 수동 방식의 `BLOB_READ_WRITE_TOKEN`도 지원합니다.
3. **`CRON_SECRET`**을 임의의 32자 이상 문자열로 추가합니다. 이것은 직원 접속 비밀번호가 아니라 자동 저장 작업의 호출 인증값입니다.
4. 최신 GitHub 코드로 **Redeploy**합니다.

새로 실행할 SQL은 없습니다. 이번 변경 전 DB의 anon 조회·수정 권한이 활성화되어 있음을 확인했습니다. 이전 안내의 `04-require-server-auth.sql`은 더 이상 실행하지 마세요. 이미 실행한 경우에는 설정된 서버용 `SUPABASE_SECRET_KEY`를 유지하면 됩니다.

## 매일 일별 목록 자동 생성

- `0 15 * * *` UTC: 한국 시간 매일 자정 예약입니다.
- Hobby 플랜에서는 실제 실행이 **00:00~00:59**에 이루어질 수 있습니다.
- 기준일은 방금 끝난 전날이고 수량은 **실제 저장 시각**의 재고입니다. 정확히 00:00 시점의 결산을 보장하지 않으며 자정 이후 입력이 포함될 수 있습니다.
- **일별 재고** 메뉴에서 날짜별 목록과 실제 저장 시각을 확인하고 CSV로 내려받을 수 있습니다.
- 품목명, 분류, 수량, 단위, 최소 재고, 메모를 보존합니다. 입출고 이력 전체나 DB 복원용 백업은 아닙니다.
- 이미 생성한 날짜는 재고를 수정하거나 작업을 재실행해도 덮어쓰지 않습니다.
- 조회·저장 실패 시 빈 재고를 성공한 목록처럼 저장하지 않습니다. 실패한 날짜를 현재 수량으로 소급 생성하지 않습니다.
- 첫 자동 실행 전에는 날짜 목록이 비어 있습니다. 작업은 Production에서 실행되며 컴퓨터나 브라우저를 켜 둘 필요가 없습니다.
- 예약 호출은 `CRON_SECRET`으로 계속 보호합니다. Blob 원본은 비공개이며 사이트 서버가 목록과 CSV를 제공합니다.

## 검증

```sh
pnpm install --frozen-lockfile
pnpm typecheck
node tests/security-daily.cjs
pnpm build
```

테스트는 공개 재고 API, 다른 출처의 쓰기 거부, Cron 호출 인증, 한국 날짜 경계, 중복 저장 방지, 원본 조회 실패 및 CSV 이스케이프를 확인합니다. Blob 테스트는 가짜 저장소를 사용합니다. 실제 Blob 저장과 예약 실행은 배포 설정 후 확인해야 합니다.

## 최초 설치에만 사용

Supabase의 `01-schema.sql`, `02-import-snapshot.sql`, `03-verify.sql`을 순서대로 한 번씩 실행합니다. 이미 운영 중인 DB에는 초기 스냅샷을 다시 넣지 않습니다.
